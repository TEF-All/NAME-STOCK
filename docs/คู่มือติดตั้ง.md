# คู่มือติดตั้ง ระบบ Stock สำเร็จรูปพร้อมใช้งาน

ระบบคลังพัสดุสำหรับหน่วยงาน: ทะเบียนพัสดุ เบิก-คืน จ่ายออก ย้ายที่เก็บ ตรวจนับ สรุปภาพรวม และหน้าผู้ดูแลระบบ
ใช้ของฟรีทั้งหมด: Google Sheets (เก็บข้อมูล) + Google Apps Script (หลังบ้าน) + GitHub Pages (หน้าเว็บ)

ใช้เวลาตั้งประมาณ 30–45 นาที · ทำตามลำดับ 1 → 7
ชื่อเมนูและค่าที่ต้องพิมพ์เขียนเป็นภาษาอังกฤษตามหน้าจอจริง พร้อมคำแปลไทยในวงเล็บ

---

## 0. สิ่งที่ต้องมี

1. บัญชี Google 1 บัญชี สำหรับเป็นเจ้าของระบบ (แนะนำบัญชีกลางของหน่วยงาน ไม่ใช่บัญชีส่วนตัว)
   ระบบทำงานในนามบัญชีนี้ และอีเมลรหัสเข้าระบบจะส่งจากบัญชีนี้ (บัญชี Gmail ทั่วไปส่งได้ประมาณ 100 ฉบับต่อวัน)
2. บัญชี GitHub ฟรี (https://github.com)
3. repo ของระบบนี้ (ที่คุณกำลังอ่านอยู่)

> ความปลอดภัย: ห้ามใส่รหัสผ่าน โทเคน หรือรหัสชีต (SHEET_ID) ลงใน GitHub
> รหัสชีตอยู่ใน Script Properties ของ Apps Script เท่านั้น · ไฟล์ `assets/config.js` เปิดเผยได้ (มีแค่ลิงก์ API และชื่อหน่วยงาน)

## 1. ชีตข้อมูล (Google Sheets)

เลือกทางใดทางหนึ่ง

**ทาง ก (แนะนำ) ให้ระบบสร้างให้** — ข้ามไปขั้นที่ 2 ได้เลย ขั้นที่ 3 จะสร้างไฟล์ชีต "ระบบ Stock — ข้อมูล" ใน My Drive ให้เอง พร้อมแท็บครบ 24 แท็บ

**ทาง ข ใช้ชีตเปล่าต้นแบบ**
1. เปิดชีตต้นแบบที่ผู้ดูแลเทมเพลตแชร์ไว้ (ชื่อ "ระบบ Stock สำเร็จรูป — ชีตเปล่า")
2. File (ไฟล์) > Make a copy (ทำสำเนา) ตั้งชื่อใหม่ตามหน่วยงาน
3. คัดลอกรหัสชีตจาก URL ส่วนที่อยู่ระหว่าง `/d/` กับ `/edit` เก็บไว้ใช้ขั้นที่ 3

ทั้งสองทาง ชีตจะถูกตั้งโซนเวลาเป็น `Asia/Bangkok` ให้ตรงกับสคริปต์ (ป้องกันวันที่ในชีตคลาดเคลื่อน)

## 2. หลังบ้าน (Google Apps Script)

1. เข้า https://script.google.com ด้วยบัญชีเจ้าของระบบ > **New project** (โปรเจกต์ใหม่)
2. ตั้งชื่อโปรเจกต์ (มุมซ้ายบน) เช่น `Stock API` (หลังบ้านระบบ Stock)
3. ไปที่ **Project Settings** (การตั้งค่าโปรเจกต์ ⚙️) > ติ๊ก **Show "appsscript.json" manifest file in editor** (แสดงไฟล์ appsscript.json)
4. กลับไปที่ **Editor** (ตัวแก้ไข) แล้วสร้างไฟล์ตามโฟลเดอร์ `apps-script/` ใน repo นี้ **ตามลำดับนี้** (กด + ข้าง Files > Script / HTML)

   | ลำดับ | ไฟล์ใน repo | สร้างเป็น | หน้าที่ |
   |---|---|---|---|
   | 1 | `appsscript.json` | แทนเนื้อหาเดิมทั้งหมด | สิทธิ์ที่ใช้ + ตั้งค่าเว็บแอป |
   | 2 | `Config.gs` | Script ชื่อ `Config` | รายการค่าตั้ง (Script Properties) |
   | 3 | `Core.gs` | Script ชื่อ `Core` | หลังบ้านหลัก |
   | 4 | `CountLib.gs` | Script ชื่อ `CountLib` | ตรวจนับ |
   | 5 | `Api.gs` | Script ชื่อ `Api` | รับคำขอจากหน้าเว็บ |
   | 6 | `Flow.gs` | Script ชื่อ `Flow` | ขั้นตอนตรวจ/ลงนามคำขอ |
   | 7 | `ReconUndo.gs` | Script ชื่อ `ReconUndo` | ยกเลิกผลนับ |
   | 8 | `Firestore.gs` | Script ชื่อ `Firestore` | (ไม่บังคับ) สำเนาอ่านเร็ว ปิดอยู่ |
   | 9 | `Setup.gs` | Script ชื่อ `Setup` | ตั้งค่าครั้งแรก |
   | 10 | `Print.html` | HTML ชื่อ `Print` | ใบพิมพ์ตรวจนับ |

   ไฟล์ `Code.gs` ที่มีมาแต่แรก ลบทิ้งได้ (คลิก ⋮ ข้างชื่อไฟล์ > Delete)
   คัดลอกทีละไฟล์: เปิดไฟล์ใน GitHub > ปุ่ม **Copy raw file** (คัดลอกไฟล์ดิบ) > วางทับใน Editor > **Save** (บันทึก ⌘S / Ctrl+S)

   > ทางลัดสำหรับผู้ใช้คอมพิวเตอร์: ติดตั้ง clasp แล้ว `clasp create --type standalone` และ `clasp push` จากโฟลเดอร์ `apps-script/`

5. (ถ้าใช้ทาง ข ในขั้นที่ 1) ไปที่ **Project Settings** > **Script Properties** (คุณสมบัติสคริปต์) > **Add script property**
   - Property (ชื่อ): `SHEET_ID` · Value (ค่า): รหัสชีตที่คัดลอกไว้

## 3. ตั้งค่าครั้งแรก (รันครั้งเดียว)

1. ใน Editor เปิดไฟล์ `Setup` > เลือกฟังก์ชัน `SETUP_1_start` ในช่องด้านบน > กด **Run** (เรียกใช้)
2. หน้าต่างขอสิทธิ์ขึ้น: **Review permissions** (ตรวจสอบสิทธิ์) > เลือกบัญชีเจ้าของระบบ
   - ถ้าขึ้น "Google hasn't verified this app" (Google ยังไม่ได้ยืนยันแอปนี้) เป็นปกติของสคริปต์ที่เราเขียนเอง
     กด **Advanced** (ขั้นสูง) > **Go to Stock API (unsafe)** (ไปที่ Stock API) > **Allow** (อนุญาต)
   - สิทธิ์ที่ขอ: ชีต Drive (ไฟล์แนบ) ส่งอีเมล (รหัสเข้าระบบ) เชื่อมต่อภายนอก (ตรวจบัตร Google) ตัวตั้งเวลา (อุ่นระบบทุก 5 นาที)
3. ดูผลที่ **Execution log** (บันทึกการทำงาน) ต้องเห็น
   - `สร้างชีตใหม่: …` หรือ `ใช้ชีต: …` · `แท็บใหม่ 24` (หรือ `มีอยู่แล้ว 24`) · `โซนเวลาชีต Asia/Bangkok`
   - `ตั้งผู้ดูแลระบบคนแรก: <อีเมลของคุณ>` ← **บัญชีที่กดรันจะเป็นผู้ดูแลระบบคนแรก**
4. ตั้งชื่อหน่วยงาน: **Project Settings** > **Script Properties** > **Edit script properties** (แก้ไข)
   - `ORG_NAME` = ชื่อหน่วยงาน (แสดงบนใบเบิก/ใบจ่าย/ใบตรวจนับ)
   - `APP_NAME` = ชื่อระบบ (ค่าเริ่มต้น: ระบบ Stock)
   - `ITEM_PREFIX` = คำนำหน้ารหัสพัสดุ ตัวอักษรอังกฤษ เช่น `ITEM` → ITEM-001 (เปลี่ยนก่อนเพิ่มรายการแรก)
   - ค่าอื่นดูคำอธิบายในไฟล์ `Config.gs`

รัน `SETUP_1_start` ซ้ำได้ทุกเมื่อ ไม่ลบหรือทับข้อมูลเดิม (ใช้ซ่อมแท็บที่ถูกลบ)

## 4. เปิดใช้งานหลังบ้าน (Deploy เป็นเว็บแอป)

1. มุมขวาบน **Deploy** (ทำให้ใช้งานได้) > **New deployment** (การทำให้ใช้งานได้รายการใหม่)
2. ⚙️ ข้าง Select type (เลือกประเภท) > **Web app** (เว็บแอป)
3. ตั้งค่า
   - Description (คำอธิบาย): `v1`
   - Execute as (เรียกใช้ในฐานะ): **Me** (ฉัน — บัญชีเจ้าของระบบ)
   - Who has access (ผู้มีสิทธิ์เข้าถึง): **Anyone** (ทุกคน — ตัวเลือกล่างสุด ไม่ต้องมีบัญชี Google)
     ระบบตรวจตัวตนเองทุกคำขอ (รหัสทางอีเมล หรือปุ่ม Google) คนที่ไม่มีสิทธิ์ดูข้อมูลไม่ได้
4. **Deploy** > คัดลอก **Web app URL** (ลิงก์ที่ลงท้ายด้วย `/exec`) เก็บไว้ใช้ขั้นที่ 5

> แก้โค้ดหลังบ้านภายหลัง ต้อง Deploy เวอร์ชันใหม่จึงจะมีผล:
> Deploy > **Manage deployments** (จัดการ) > ✏️ แก้ไข > Version (เวอร์ชัน): **New version** (เวอร์ชันใหม่) > Deploy · ลิงก์ `/exec` เดิมไม่เปลี่ยน
> แก้ Script Properties ไม่ต้อง Deploy ใหม่

## 5. หน้าเว็บ (GitHub Pages)

1. สร้าง repo ของหน่วยงานจาก repo นี้
   - ถ้า repo นี้ตั้งเป็น template: ปุ่ม **Use this template** (ใช้เป็นต้นแบบ) > **Create a new repository**
   - หรือ **Fork** แล้วเปลี่ยนชื่อ
   - ต้องตั้งเป็น **Public** (สาธารณะ) ถ้าใช้ GitHub ฟรี (GitHub Pages ของ repo ส่วนตัวต้องจ่ายเงิน) · repo ไม่มีข้อมูลหรือรหัสลับ เปิดเผยได้
2. แก้ไฟล์ `assets/config.js` ใน GitHub (เปิดไฟล์ > ✏️ **Edit**)
   - `API_URL:` วางลิงก์ `/exec` จากขั้นที่ 4 ในเครื่องหมาย '…'
   - `ORG_NAME` / `ORG_NAME_EN` ชื่อหน่วยงานไทย/อังกฤษ · `APP_NAME` / `APP_NAME_EN` ชื่อระบบ
   - `ITEM_PREFIX` ต้องตรงกับ Script Property `ITEM_PREFIX`
   - `SUPPORT_EMAIL` อีเมลติดต่อผู้ดูแล (แสดงหน้าเข้าสู่ระบบ) · ว่างได้
   - `LOGO_URL` โลโก้หัวกระดาษ: อัปโหลดรูปไว้ในโฟลเดอร์ `assets/` แล้วใส่ เช่น `'assets/logo.png'` · ว่าง = ไม่แสดง
   - `FORMS` หัวกระดาษ ชื่อใบ และช่องลงนามของแบบฟอร์มพิมพ์ (ดูข้อ 7.5) · ไม่แก้ก็ใช้ได้
   - กด **Commit changes** (บันทึกการเปลี่ยนแปลง)
3. **Settings** (การตั้งค่า) > **Pages** > Source (แหล่งที่มา): **Deploy from a branch** (เผยแพร่จาก branch)
   > Branch: `main` · Folder: `/ (root)` > **Save**
4. รอ 1–2 นาที ลิงก์หน้าเว็บจะขึ้นด้านบน เช่น `https://<บัญชี>.github.io/<ชื่อ repo>/`
5. กลับไป Apps Script > **Project Settings** > **Script Properties** > เพิ่ม
   - `FRONT_URL` = ลิงก์หน้าเว็บจากข้อ 4 (ลงท้ายด้วย `/`)

## 6. เข้าสู่ระบบครั้งแรก + ตั้งผู้ใช้

1. เปิดลิงก์หน้าเว็บ > ใส่อีเมลบัญชีเจ้าของระบบ > **ส่งรหัสเข้าอีเมล** > ใส่รหัส 6 หลักจากอีเมล
2. เข้าได้ = ผู้ดูแลระบบ (ADMIN) · ไปหน้า **ผู้ดูแลระบบ** > **เพิ่มรายการใหม่** (พิมพ์หมวดหลักใหม่ได้)
3. เพิ่มผู้ใช้: เปิดชีตข้อมูล > แท็บ `MASTER_ผู้ใช้` > เพิ่มแถว

   | อีเมล | ชื่อ | ตำแหน่ง | บทบาท | อนุมัติขั้น | สิทธิ์ขาด | ใช้งาน |
   |---|---|---|---|---|---|---|
   | อีเมลผู้ใช้ | ชื่อที่แสดง | ตำแหน่ง | `ADMIN` / `STAFF` / `AUDITOR` | 1 (เฉพาะ ADMIN) | ไม่ | ใช่ |

   - `ADMIN` ผู้ดูแล: อนุมัติ จ่าย รับคืน จัดการรายการ (ควรมีอย่างน้อย 2 คน เพราะอนุมัติคำขอของตัวเองไม่ได้)
   - `STAFF` เจ้าหน้าที่: ขอเบิก ตรวจนับ ดูสรุป
   - `AUDITOR` ผู้ตรวจสอบ: ดูอย่างเดียว
   - ปิดสิทธิ์: เปลี่ยนคอลัมน์ ใช้งาน เป็น `ไม่` (ไม่ต้องลบแถว)
   - คนนอก (อีเมลอื่น) เข้าได้เองหลังกรอกแบบสอบถาม ถ้าไม่ต้องการ ตั้ง Script Property `EXTERNAL_SIGNUP` = `0`
4. สถานที่เก็บ: แท็บ `MASTER_สถานที่` (มี "คลังหลัก" ให้แล้ว แก้ชื่อหรือเพิ่มได้)

## 7. (ไม่บังคับ) ตั้งเพิ่มเติม

### 7.1 มีรายการพัสดุเดิมอยู่แล้ว
1. วางรายการลงแท็บ `ทะเบียนพัสดุ` ตั้งแต่แถว 2 · คอลัมน์ A รหัส (เช่น ITEM-001) · B ชื่อ · E หมวดหลัก · G ยอดยกมา · K ที่เก็บ
2. Apps Script > ไฟล์ `Core` > ฟังก์ชัน `SETUP_importOpeningBalances` > **Run** (ทำได้ครั้งเดียว ก่อนมีการเบิกจ่าย)
3. คงเหลือในระบบ = ยอดยกมา · หลังจากนี้ทุกการเปลี่ยนแปลงลงแท็บ `LEDGER_เคลื่อนไหว`

### 7.2 ปุ่ม Sign in with Google (แทนรหัสทางอีเมล)
1. https://console.cloud.google.com > สร้างโปรเจกต์ > **APIs & Services** > **OAuth consent screen** (หน้าจอขอความยินยอม) ตั้งค่าแบบ External
2. **Credentials** (ข้อมูลเข้าสู่ระบบ) > **Create credentials** > **OAuth client ID** > Application type: **Web application**
3. **Authorized JavaScript origins** (ต้นทาง JavaScript ที่ได้รับอนุญาต): `https://<บัญชี>.github.io`
4. คัดลอก Client ID (ลงท้าย `.apps.googleusercontent.com`) ไปใส่
   - `assets/config.js` ช่อง `CLIENT_ID`
   - Script Property `GIS_CLIENT_ID`
5. Client ID เปิดเผยได้ (ไม่ใช่รหัสลับ) · **ห้ามใส่ Client secret ที่ไหนเลย**

### 7.3 เจ้าหน้าที่ใช้อีเมลโดเมนองค์กร (Google Workspace)
- Script Property `STAFF_DOMAIN` = `example.org` และ `assets/config.js` ช่อง `STAFF_DOMAIN` ค่าเดียวกัน
- อีเมลโดเมนนี้ได้บทบาท STAFF อัตโนมัติ ไม่ต้องเพิ่มในทะเบียนผู้ใช้
- ถ้าเข้าด้วยปุ่ม Google แล้วถูกปฏิเสธ ดูค่า hd ใน Executions แล้วตั้ง `STAFF_HD`

### 7.4 สำเนาอ่านเร็วใน Firestore
ปิดอยู่ ไม่จำเป็นสำหรับหน่วยงานทั่วไป · วิธีเปิดดูหัวไฟล์ `Firestore.gs`
ระบบใช้สำเนาเฉพาะเมื่อสร้างหลังการบันทึกล่าสุด ไม่งั้นอ่านจากชีตเสมอ (ไม่แสดงยอดค้าง)

### 7.5 หัวแบบฟอร์มและช่องลงนาม (ใบเบิก ใบจ่าย ใบย้าย ใบตรวจนับ)
แก้ที่ `assets/config.js` ส่วน `FORMS` (ไม่ต้องแตะ Apps Script ไม่ต้อง Deploy ใหม่)

| ช่อง | ใช้ทำอะไร | ตัวอย่าง |
|---|---|---|
| `HEADER_1` `HEADER_2` `HEADER_3` | หัวกระดาษ 3 บรรทัด (ว่าง = ชื่อหน่วยงานไทย/อังกฤษ) | `'เลขที่ 1 ถนน… โทร 02-000-0000'` |
| `FOOTER` | ท้ายกระดาษ (ว่าง = ชื่อระบบ) | `'แบบฟอร์มนี้พิมพ์จากระบบ'` |
| `PER_PAGE` | จำนวนรายการต่อหน้า | `10` |
| `BORROW` / `GIVE` / `ISSUE` / `TRANSFER` / `COUNT` | ใบเบิก-คืน / ใบจ่ายออก / ใบจ่ายตรง / ใบย้าย / ใบตรวจนับ | |
| `TITLE: ['ไทย', 'English']` | ชื่อใบ | `['ใบยืมอุปกรณ์', 'Equipment Loan Form']` |
| `SIGNS: [['ไทย','English'], …]` | ช่องลงนาม เพิ่ม/ลดจำนวนได้ (ใบตรวจนับได้สูงสุด 4 ช่อง) | `[['ผู้ยืม','Borrower'], ['หัวหน้างาน','Supervisor'], ['ผู้อนุมัติ','Approved by']]` |

ใบเบิก-คืนและใบจ่ายออก: **ช่องแรก = ผู้ขอ · ช่องสุดท้าย = ผู้อนุมัติ** ระบบวางลายเซ็นอิเล็กทรอนิกส์ลงสองช่องนี้

## หลักการข้อมูล (ควรรู้)

- คงเหลือ = ผลรวม เข้า − ออก ในแท็บ `LEDGER_เคลื่อนไหว` เสมอ · คอลัมน์ G ของทะเบียน (ยอดยกมา) เป็นข้อมูลอ้างอิง
- "ลบรายการ" = เปลี่ยนสถานะเป็น เลิกใช้ + ตัดยอดเหลือ 0 · แถวไม่ถูกลบ ประวัติอยู่ครบ · เปิดใช้งานอีกครั้งได้จากหน้าผู้ดูแลระบบ
- รายการที่เลิกใช้ไม่แสดงในหน้าตรวจนับ
- บันทึกผลนับแล้ว คงเหลือปรับเป็นยอดนับอัตโนมัติ (ลงบรรทัด "ปรับยอด") · ยกเลิกผลนับ = ลงบรรทัดกลับรายการ
- ห้ามลบแถวในแท็บประวัติ ถ้าบันทึกผิดให้ลงรายการปรับยอด/กลับรายการผ่านหน้าเว็บ
